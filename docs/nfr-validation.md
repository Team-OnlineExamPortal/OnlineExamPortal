# Non-functional requirement evidence

This file distinguishes local evidence from requirements that need the shared attempt APIs or a deployed environment.

| Issue | Requirement | Local evidence | Status |
| --- | --- | --- | --- |
| #18 / NFR-003 | Start an available exam within 3 clicks from the dashboard | Walkthrough: sign in (1 click), then click **Start exam** on the available-exams dashboard (2 clicks total). The dashboard action opens the exam and starts the attempt directly; there is no details or confirmation step. `client/src/App.test.jsx` checks that the attempt API is called from this direct action. | Verified in client component test; API is mocked. |

| #16 / NFR-001 | p95 for attempt API requests is at most 500 ms | `server/scripts/load-test-attempt.js` and `npm run perf:attempt` measure p50/p95/p99 under configurable concurrency and duration. No agreed deployment load profile is recorded. | Local probe passed; deployment acceptance remains unverified until measured on a representative deployment under the agreed profile. |
| #17 / NFR-002 | 99.9% availability during exam windows | Availability is an operational measurement over a deployed exam window; the repository has no deployment target or monitoring data. | Unverified; requires a deployed service and monitoring evidence. |

The domain-only command is also useful when changing question selection or scoring without running the full server suite. The load runner expects `OEP_ATTEMPT_URL` to point to an authenticated active-attempt read endpoint and `OEP_STUDENT_TOKEN` to be a staging student token. Defaults are 20 concurrent workers for 30 seconds and a 500 ms p95 limit; treat that profile as provisional until the team/faculty agrees to it. The runner only performs reads.
